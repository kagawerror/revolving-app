# Developer Setup

Steps to get `rev_app` running locally against Firebase + Cloudinary.

## 1. Install dependencies

```sh
flutter pub get
```

## 2. Cloudinary (proof image uploads)

Proof images are uploaded directly from the client using an **unsigned** upload
preset (the API secret is never embedded in the app).

1. Copy the example env file:
   ```sh
   cp .env.example .env
   ```
2. In the Cloudinary console, create an **unsigned** upload preset.
3. Fill in `.env`:
   - `CLOUDINARY_CLOUD_NAME` — your cloud name
   - `CLOUDINARY_UPLOAD_PRESET` — the unsigned preset name
   - `CLOUDINARY_UPLOAD_FOLDER` — (optional) e.g. `rev_app/proofs`
4. Run the app, loading the env at build time:
   ```sh
   flutter run --dart-define-from-file=.env
   ```

`.env` is gitignored — never commit the real file.

## 3. iOS Firebase configuration

Android initializes Firebase automatically from `google-services.json` via the
Gradle plugin. iOS needs platform options generated by FlutterFire:

```sh
flutterfire configure
```

This generates the gitignored `lib/firebase_options.dart` and the iOS
`GoogleService-Info.plist`. After running it, switch the
`Firebase.initializeApp()` call in `lib/main.dart` to:

```dart
Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)
```

(with `import 'firebase_options.dart';`).

## 4. Deploy Firestore rules + indexes

Security rules live in `firestore.rules`; the composite index required by
`FundRepository.watchByCompany` (`companyId` + `name`) lives in
`firestore.indexes.json`. Both are wired via `firebase.json`. Deploy with:

```sh
firebase deploy --only firestore
```

## 5. Seed an initial admin

There is no self-signup for admins. Bootstrap one manually:

1. Create a user in **Firebase Authentication** (email/password).
2. In Firestore, create a `users/{uid}` document (where `{uid}` is that auth
   user's UID) with at least:
   - `role: "admin"`
   - `companyId: "<an existing companies/{id}>"`
   - `displayName: "<name>"`

The admin can then create companies and funds, and provision other users
(incharge, approvers, employees) from within the app.
